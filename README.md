## Работа

Кнопка получает **свежий неизменённый** `iframe_uri` из `https://api.liftw.ws/info/3637` с `mode:cors`, `cache:no-store`, `credentials:omit`. Публичный config содержит только endpoint, ID и ожидаемый origin. Подписанные URL существуют в памяти вкладки/атрибуте iframe; не записываются в Git, CacheStorage, localStorage, логи или экспорт. Backend, аккаунты и новые разрешения не нужны. Отказ CORS/сети/региона/домена фиксируется без обхода. HTTP 200, load, playerReady, startWatching, viewProgress и ручное наблюдение разделены.

Разрешены сообщения только от текущего `contentWindow` и точного `https://embed.liftw.ws`. Фиксированная схема событий; числа ограничены; вложенные payload не сохраняются. На каждой перезагрузке создаётся новое окно. Единственная исходящая команда — найденный в штатном шаблоне `ping`. Внешний публичный контракт pause/seek не установлен. Нет управления cross-origin DOM, автоперехода, метрики покрытия и флага «Просмотрено». Fullscreen/PiP — разрешения iframe и ручная проверка средствами плеера.

Журнал пишется синхронно после каждого события, на visibility/pagehide и сетевых изменениях. На прогон не более 3000 событий; число отброшенных явно экспортируется. Прогоны не удаляются автоматически. При переполнении/недоступности хранилища видна ошибка и доступен экспорт из памяти. Старое повреждённое значение не перезаписывается. Safari и standalone имеют разные текущие прогоны. Экспорт содержит все сохранённые прогоны, UTC и ID; user-agent включается только явным флажком. Произвольные URL/секретные поля удаляются на границе экспорта. Ручные выводы о рекламе относятся только к конкретному сеансу.

## Сохранение и откат

Исходный активный commit: `6e80f7756abeee359a674fe8a21afeaaf235d0b8`.
Архив: https://github.com/MawrikBorug/kadr-video-lab/tree/archive/pre-lift-6e80f77

Все прежние исходники, подключения и тесты доступны там и в истории Git. Исторические `docs/`, `evidence/`, `protocol/` сохранены; бывший `web/data/` перенесён без изменения байтов в `history/data/`. Эти материалы не входят в активную сборку Pages. Контрольные суммы проверяются перед сдачей.

Прежний браузерный журнал `kadr.videoLab.v1` не изменяется. Кнопка «Экспорт старых данных» доступна на главной странице. Git не содержит данных, остававшихся только на телефоне; удаление данных сайта самим пользователем может их уничтожить. Стенд не вызывает localStorage.clear(), удаление IndexedDB или широкую отмену service worker. Новый worker по прежнему `sw.js`/scope немедленно заменяет старый и удаляет только `kadr-lab-<12 hex>` с запросами исключительно внутри этого стенда. Он не содержит fetch handler и не обещает offline/PWA-установку. Онлайн-навигация старого worker была network-first и получает новый интерфейс; активный старый экран обновится при следующем открытии/обновлении страницы.

Откат без переписывания истории (в чистом рабочем дереве):

```sh
git switch main
git pull --ff-only
git restore --source=origin/archive/pre-lift-6e80f77 --staged --worktree -- .
git commit -m "Restore archived video lab before Lift"
git push origin main
```

Pages снова соберёт архивную версию; её worker заменит миграционный. Браузерные ключи прежнего стенда сохраняются.

## Проверки и публикация

Node 24+, Python 3. В проекте нет runtime-зависимостей.

```sh
npm ci --ignore-scripts
npm test
npm run build
node scripts/check-public.mjs
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:browser
npm run package
```

Unit и локальные browser-тесты используют **искусственные** ответы, не доказывают события Lift. CI публикует только `main` через существующий `.github/workflows/pages.yml` и проверяет commit на живом адресе. Снимки/trace/HAR реального сетевого сеанса автоматически не сохраняются из-за временных URL.

Владелец получает только ссылку: запуск → минута просмотра → pause/seek → fullscreen/PiP/фон → обрыв сети → перезагрузка и сравнение позиции → отдельный полный просмотр оригинала → экспорт JSON. Короткая функциональная часть повторяется с экрана «Домой». Телефонный опыт и полный рекламный сеанс выполняются владельцем после публикации; manifest не считается доказательством установки PWA.
