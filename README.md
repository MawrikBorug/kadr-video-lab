# КАДР · текущий видеоопыт Lift и WebTorrent (lift-2)

Одна рабочая ссылка: https://mawrikborug.github.io/kadr-video-lab/

Расширен существующий стенд. Основной `MawrikBorug/kadr` не изменяется; архитектура продукта не выбрана. Старые поставщики и массовые очереди не возвращаются. Публикация — прежний main → GitHub Actions → Pages.

## Подготовленные подключения

- **Lift:** штатный свежий iframe через публичный CORS API, без backend. Sintel (3637, 2010) доступен для медиапробы только с Eng.Original. Шесть других произведений — каталожные пробы, без запуска защищённого медиа при неустановленном допуске.
- **A / WebTorrent, WebRTC only:** актуальный browser ESM WebTorrent 3.0.21, `webSeeds:false`, только совместимые WebRTC-пиры. HTTP загружает лишь .torrent metadata. Предлагаются открытый Sintel и собственный контроль 60 с. Контроль требует временной браузерной вкладки-сидера разработчика; это не автономность публичного swarm.
- **B / WebTorrent, HTTP webseed only:** трекеры, DHT/PEX и P2P отключены; внешний разрешённый webseed `webtorrent.io/torrents/`. Собственный HTMLVideoElement получает Range-поток от браузерного service worker по `./webtorrent/`. Это локальный мост из кусков в браузере, не медиасервер КАДРа. Весь фильм в Blob перед стартом не загружается.
- **Lampac не подключён:** в прежних исследованиях и проверенных официальных материалах нет квалифицированного внешнего URL с разрешёнными бесплатными условиями без карты/партнёрки. Не проверены CORS, конкретный источник и маршрут видео такого экземпляра. Сервер не устанавливался; случайные открытые экземпляры не используются.

Гибрид не добавлен: для этого опыта транспорты изолированы, и HTTP не выдаётся за P2P. Публичный Webtor/API не используется.

## Почему могли остаться 60 секунд

В `player-venom@0.3.6` progress tracker подавляет сохранение/отправку первые 60 с после начальной позиции или скачка между timeupdate более 4 с. Lift задаёт `trackProgress:9`: после подавления нормальный поток целых медиасекунд даёт события примерно через 10 с. В библиотеке есть отдельное собственное сохранение `vp.<id>` с порогом >10 с, тоже после 60-секундного окна. Повторный запуск с 60 с и просмотр менее минуты до нового запуска могут оставить именно 60 с. Фон/редкие timeupdate также могут сбрасывать окно. Это вывод по коду и искусственной модели, не измеренная частота телефонного потока.

По описанию первого прогона 126bdadb-c16f-4870-aa63-56a1743bd71a известны шесть успешных API, playerReady/startWatching/pong и одно viewProgress около 60/888. Сырой телефонный JSON в переданных ссылках не предоставлен; точную единственную причину пропуска следующих сообщений по описанию установить нельзя. Прежний collector принимает корректные числовые time/duration без округления до минуты. Общий предел 30 сообщений/с в старом harness мог теоретически отбрасывать события; в новом пути валидный progress этим порогом не отбрасывается. Счётчики доверенных, принятых progress и причин отказа, интервалы прихода и поколение iframe позволяют проверить реальную потерю на следующем телефоном прогоне.

Ранее стенд отправлял только `ping`, не позицию. Восстановление владельца выполнял Lift/его плеер, не стенд. У библиотеки найден внутренний URL-параметр `t`, но подтверждённого внешнего Lift seek/restore контракта нет. Подписанный iframe URL не дополняется и не переписывается; команды не угадываются и cross-origin DOM не читается.

После нового запуска текущая позиция неизвестна до первого нового события. Историческое число показывается отдельно с UTC; таймер меняет только возраст измерения. У native HTML-плеера есть отдельная явная кнопка передачи позиции **до запуска** через `currentTime`; запрошенная позиция и последующие seeked/playing записываются отдельно. Это не реализация внешнего seek Lift.

## Сохранность и изоляция

Исходный HEAD перед расширением: `f7006deb9d58898ca61da219b3d31f4bf6ef5a89`.
Архив: https://github.com/MawrikBorug/kadr-video-lab/tree/archive/pre-expansion-f7006de

Существующие `kadr.lift.journal.v1`, `kadr-lift-experiment-position` и старый `kadr.videoLab.v1` не перезаписываются и не удаляются. Первый Lift-журнал включается в общий экспорт и имеет отдельную кнопку резервного экспорта; архивный журнал прежних поставщиков также экспортируется без запуска. Git не содержит данных, остававшихся только в браузере владельца. Старый глобальный ключ позиции импортируется исключительно как история Lift/Sintel, никогда как позиция другого материала или транспорта.

Новые записи — `kadr.videoLab.experiments.v1`, schema 3. Ключ позиции: подключение + материал + сезон + эпизод. Каждый прогон имеет UUID, build, UTC, режим browser/standalone, поколение источника, каталог, ручные наблюдения, телеметрию и транспорт. Переключение ждёт destroy предыдущего клиента; источник и диапазоны прежнего прогона не примешиваются к новому. Позиции и журналы сохраняются часто; visibility/pagehide фиксируются. Native timeupdate журналируется не чаще ~1 Гц, без изменения значения времени; переходы состояния/seek/ended сохраняются отдельно. Лимит 3000 событий с явным droppedEvents; прогонов автоматически не удаляем. При повреждении/недоступности/quota исходные значения сохраняются, остаётся экспорт из памяти.

Экспорт и таблица сравнения доступны на странице. UA по умолчанию выключен и включается явным флажком. Подписанные URL, query, произвольные вложенные payload, адреса пиров/SDP, ключи и cookies не сохраняются. Реальный iframe URI живёт только в памяти и атрибуте текущего iframe. Принимаются только точный origin и текущий contentWindow; известные поля и ограниченные конечные числа.

## Честный учёт торрентного транспорта

Счётчики payload подключены к настоящим `wire.download` с проверенными типами `webrtc` / `webSeed` WebTorrent 3.0.21. Это байты payload с повторами; `file.downloaded` показан отдельно. Неизвестный или запрещённый транспорт закрывается. Число кандидатов сигнализации отделено от подключённых пиров. Metadata bytes не считаются HTTP-медиабайтами.

Первый `playing` записывает wall-clock startup и `file.downloaded < file.length`. На seek фиксируются настоящий native seeking/seeked/playing, media buffered и Range браузера: был ли первый требуемый piece пуст на момент запроса. «Вне media buffer» отдельно не объявляется «не загружено». Восстановление сети оценивается по новым событиям, без искусственных таймеров просмотра. Флаг «Просмотрено», покрытие интервалов и очередь не реализованы: ended сам по себе не означает ≥90% уникального просмотра.

`SessionPieceStore` использует новый случайный OPFS-каталог для каждого клиента/прогона; при недоступном writable OPFS — изолированный RAM store с пределом 192 MiB. Стартовые старые куски не используются. Локальный URL потока также получает новый случайный идентификатор сеанса, чтобы браузерный media cache не подменял новый транспортный прогон. Destroy удаляет только собственный каталог. В официальном browser bundle обнаружено импортное удаление общего OPFS/chunks; сборка удаляет только эту точную побочную операцию (проверяемое единственное совпадение), сохраняя сетевую реализацию SDK. Патч и лицензия описаны в публичном vendor/NOTICE.txt. Это исключает ложный P2P-успех за счёт общей папки сидера и зрителя и затрагивание чужих кэшей. После аварийной выгрузки страницы временные каталоги могут остаться до очистки данных сайта; новый прогон их не читает. Журналы при штатной остановке не очищаются.

Прежний SW/scope сохранён. Удаляются только установленные старые кэши `kadr-lab-<12 hex>` с запросами целиком внутри стенда. Новый SW добавляет локальный streaming bridge SDK; Lift/API/внешнее медиа не кэширует. Manifest и этот worker не доказывают установку полноценной PWA или offline-воспроизведение.

## Проверки и публикация

Node 24+, Python 3. WebTorrent закреплён в lockfile, runtime использует browser bundle. Node TCP Torrent-клиент в медиапробах не запускается.

```sh
npm ci --ignore-scripts
npm test
npm run build
node scripts/check-public.mjs
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:browser
npm run package
```

Локальные browser-тесты — искусственные Lift inputs и настоящий browser WebTorrent на собственном HTTP fixture. Они не доказывают Lift telemetry, внешний webseed или публичный P2P. Реальные отдельные пробы делает scripts/check-expansion-live.mjs, сохраняя только обезличенные результаты. В этой cloud среде Node HTTP-проверки выполняются с `NODE_USE_ENV_PROXY=1`; браузер использует настроенный proxy с сохранением TLS-проверки. Трассы/HAR не записываются.

CI публикует main, проверяет live build-info.json/commit, шесть каталожных записей и текущие файлы. Откат без force push: `git restore --source=origin/archive/pre-expansion-f7006de --staged --worktree -- .`, новый commit и push в main. Старые браузерные ключи остаются совместимыми с архивом.

Владельцу после сдачи: Lift/Sintel 150 с без seek/фона → пауза/seek/фон и сравнение last UTC → по одной каталожной пробе → B/Sintel с ранним play, дальним seek и обрывом → A отдельно с честными счётчиками → JSON/сравнение. Режим «Домой» отдельным прогоном. Владелец не ищет ID, не запускает сервер и не деплоит. Полный рекламный сеанс/телефонное расширение остаются будущими испытаниями.
