# КАДР · Lift + браузерный WebTorrent (lift-3)

Рабочий адрес: https://mawrikborug.github.io/kadr-video-lab/

Доработка существующего стенда по телефонной проверке. Основной `MawrikBorug/kadr` не меняется. Архитектура видео не принята. Lampac, серверы, аккаунты, платные сервисы и ноутбук не устанавливаются/не настраиваются. Исключённые поставщики остаются только в истории.

Наличие metadata или load не означает видео. Проверки ID, original/year/type, пустого original через точное name, HTTPS origin и пути iframe сохранены. Подпись/host/регион/авторизация не переписываются, DRM/ограничения не обходятся. Backend не добавлен: используется браузерный публичный CORS API.

Сезон и эпизод выбираются из снимка штатной конфигурации. Смена элемента закрывает предыдущий источник и создаёт отдельный прогон. Native embed содержит обработчики `playlist hook` → `playlist hooked`, `playlist go {season,episode}` и `changeEpisode`. Стенд использует только эти найденные сообщения, проверяя origin/contentWindow. Запрос выбора и реальный ответ разделены; отсутствие ответа обозначается явно, повтор доступен. `lastEpisode` — история поставщика, не подтверждение текущей серии. Позиция выбранного эпизода не обновляется до совпадающего `changeEpisode` по сезону/эпизоду. Numeric id от progress сохраняется отдельно: он может обозначать медиа/озвучку и не считается автоматически ID элемента каталога. Ended не доказывает серийную идентичность при неподтверждённой серии.

Заявленные дорожки/качества и ручные результаты main video, RU sound, quality, subtitles, ads, navigation, seek, restore, episode selection/end хранятся отдельно. Найденная метка 4K не означает испытанное 4K, название дорожки не означает услышанную речь.

## Минутное плато Lift

Первый телефонный прогон `126bdadb-c16f-4870-aa63-56a1743bd71a` известен по описанию владельца: единственный progress около 60/888, шесть API success, playerReady/startWatching/pong, без ended, browser/standalone=false. Сырой телефонный JSON в переданной папке не предоставлен.

Путь данных: native `viewProgress(time,duration)` → exact origin + current contentWindow → конечные допустимые числа → журнал + отдельная позиция с UTC. Общий старый предел 30 сообщений/с уже снят для валидных сообщений. Счётчики входящих/принятых/отказов и интервалы прихода сохраняются; искусственный burst-тест не объявляется настоящим событием Lift.

В найденном SDK player-venom 0.3.6 tracker подавляет прогресс и собственное сохранение первые 60 медиасекунд после начальной позиции или скачка >4 с между timeupdate. Embed задаёт trackProgress=9: при непрерывном просмотре ожидаются 60,70,80…; собственный save имеет порог >10 с. Частые перезапуски с позиции 60 до достижения 120 или редкие фоновые timeupdate могут удержать число 60. Это объяснение проверяется реальным наблюдением отдельно от модели; оно не доказывает уникальную причину первого телефона.

Стенд не отправлял и не отправляет Lift seek/restore. Собственное восстановление Lift не объявляется нашим. Внутренний SDK-параметр t не является установленным внешним контрактом: signed URL им не дополняется. Native HTML-плеер WebTorrent имеет отдельную явную передачу currentTime с последующим seeked; это другой интерфейс.

Новая панель диагностики записывает фазы запуска/непрерывных 150 с/паузы/seek/до-после reload: поколения, UTC, счётчики, последнюю реальную позицию и необязательное вручную прочитанное время. Оно не превращается в telemetry/restore. Таймер считает только длительность наблюдения и возраст измерения, не ход видео. При новом запуске текущая позиция неизвестна до нового события; старая показана как история с UTC.

Реальный контроль на официальном liftw.ws подтвердил первое событие около 60 с, затем шаг примерно 10 медиасекунд при непрерывном просмотре дольше двух минут. Пауза на 12 с не создала нового минутного окна. После native seek возникло новое окно около 60 с. При перезагрузке сам Lift показал 03:12 (предыдущее событие 192.123 с); первое новое событие было 252.215 с. Стенд в этом опыте не участвовал и seek не отправлял. Это подтверждает механизм в данной сессии, но не уникальную причину плато первого телефона. Протокол, UTC и существующие снимки приложены к сдаче. Успех на liftw.ws не доказывает стороннее встраивание на github.io или iPhone. Отдельный неуспешный запуск с HTTP 403 также сохранён.

## A: только WebRTC, без webseed

WebTorrent 3.0.21 — browser ESM; `webSeeds:false`. Собственный поток HTMLVideoElement получает проверенные куски через browser SW Range; Node TCP и Webtor не используются. HTTPS metadata не считаются HTTP-медиабайтами. Допустимы только WebRTC wires; неизвестный транспорт закрывается.

Этапы фиксируются отдельно: library → SW → metadata/identity → ответы трекеров → кандидаты → ICE/datachannel → BitTorrent wire → bytes → stream/loadedmetadata/playing. Public peer count, payload bytes и уникальные байты файла разделены. Изолированная local ICE-проба считает кандидаты без хранения IP/SDP; это не число сидеров и не доказательство доступности публичного swarm.

Нулевые медиабайты приводят к **тайм-ауту 45 с**, коду последнего сбоя, destroy соединений и возможности повтора. Отсутствие кандидата не переименовывается в доказанное отсутствие сидеров; отсутствие ответа трекера, ICE failure, wire без payload и незагруженные metadata различаются. HTTP fallback отсутствует.

В управляемом облачном Chromium обнаружена политика `WebRtcIPHandling=disable_non_proxied_udp`: нативная datachannel-проба собирает 0 ICE-кандидатов и без SDK. Политика не менялась. Контролируемый браузер-сидер разработчика запускается до зрителя, infohash сверяется, store отделён; попытка с ним отделена от публичных раздач. Владелец сидер/сервер не запускает, кнопки сидера из пользовательского интерфейса убраны. Постоянного сидера нет, его вкладка после пробы закрывается. Эта облачная граница не объявляет P2P невозможным на iPhone и не доказывает отсутствие совместимых пиров в Интернете.

## B: только torrent/HTTP webseed

В B tracker/DHT/PEX/WebRTC отключены; допустим только `wire.type=webSeed`. Прямого video.src на внешний фильм нет: src всегда scoped SW streamURL с новым случайным идентификатором прогона. SDK проверяет pieces по torrent hashes; один ordinary HTTP URL без подходящей metadata не принимается.

Для **всех десяти желаемых произведений квалифицированный разрешённый webseed не найден** в проверенных поисковых результатах и официальном free-torrents inventory WebTorrent. Это граница найденных ресурсов, не утверждение об отсутствии файлов во всём Интернете. Не найден комплект: разрешённое распространение + конкретный torrent/infohash + соответствующий byte source + CORS/Range. Плеер Lift не подменяется торрентом другой работы или трейлером.

Поэтому техническая выборка B отдельно расширена:

Внешние четыре источника — официальный `webtorrent.io/free-torrents`, public domain/Creative Commons. Собственный маленький контроль использует уже существующий static Pages endpoint как webseed того же файла (не отдельный сервер); в A этот HTTP-источник отключён. Метаданные и образцы bytes webseed сверены по Content-Range/размеру/SHA1 torrent piece; результаты приложены. Закреплённые infohash/filename/size проверяются клиентом. Runtime videoWidth/Height/MediaError и реальные playing/seeked фиксируются отдельно от этих сведений. Полноценная русская речь в тонах не заявляется.

На браузерах с native audioTracks API можно выбрать предоставленную дорожку; запрос enabled записывается, услышанный звук остаётся ручным наблюдением. При отсутствии API это ограничение показано явно. Весь фильм перед стартом в Blob зрителя не загружается. Полный File читает только явно помеченный временный сидер маленького разрешённого fixture.

## Журналы, архив и откат

HEAD до работы: `731735f55df9919202e359ecfa38bb0880e6afc8`.
Архив: https://github.com/MawrikBorug/kadr-video-lab/tree/archive/pre-phone-fixes-731735f

Ключ schema3 `kadr.videoLab.experiments.v1` сохранён. Позиции разделены connection/material/season/episode/providerEpisodeId; для одиночного контроля прежние ключи совместимы. Старый открытый прогон lift-2 сохраняется и не получает события новой сборки: создаётся новый прогон. Старые v1/v2 keys, журналы и архивные результаты не удаляются, их экспорт остаётся доступен. Git не содержит данных только из браузера владельца; резервный JSON выгружается на том же устройстве. Повреждение/quota показываются, экспорт из памяти остаётся. UA — явный необязательный флажок, default off.

MAX_EVENTS=3000 с явным droppedEvents; автоматического удаления прогонов нет. Поля сообщений фиксированы; free payload/URL, подписи, ключи, cookies, IP/SDP пиров не сохраняются. Safari visibility/pagehide/online/offline/standalone фиксируются. Native timeupdate — реальные значения, выборка не чаще ~1 Гц.

SW URL/scope прежние, новый streaming handshake lift-3. Удаляются только старые shell caches kadr-lab-<12hex> с запросами целиком внутри стенда; чужие кэши не удаляются. Отдельный SessionPieceStore OPFS/RAM и nonce потока исключают повторное использование кусков/медиакэша как ложное P2P. Удаление общего OPFS/chunks в pinned bundle по-прежнему удалено точным проверяемым патчем; сеть SDK не меняется. Destroy удаляет только собственную папку. После аварийного закрытия временные папки могут остаться, новые сеансы их не читают. RAM fallback ограничен 192 МиБ: полная большая раздача в этом режиме может упереться в явный лимит.

Откат разработчиком без force push: `git fetch origin`, затем `git restore --source=origin/archive/pre-phone-fixes-731735f --staged --worktree -- .`, commit и push в main. Pages опубликует архивную оболочку. Браузерные журналы автоматически не очищаются при откате.

## Проверки

Node 24+, Python3. Разработка/сборка не поручаются владельцу.

```sh
npm ci --ignore-scripts
npm test
npm run build
node scripts/check-public.mjs
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:browser
npm run package
```

`node scripts/refresh-lift-catalog.mjs` — разработческое обновление metadata без сохранения подписанных URLs. `scripts/check-expansion-live.mjs` — реальные browser probes и экспорт (без HAR/trace). Локальные Lift fixtures синтетические; actual browser WebTorrent local HTTP test не является публичным P2P. Реальные публичные проверки выполняются после Pages deploy; физический iPhone отдельный. `NODE_USE_ENV_PROXY=1` в данной облачной среде применяется только к Node HTTP, не отключает TLS/сетевые политики.

«Просмотрено», 90% уникального покрытия и очереди не реализованы. EndedSoon ≠ ended, сумма time-дельт не используется. Manifest не означает установленную PWA. Отсутствие рекламы за весь каталог не заявляется.
