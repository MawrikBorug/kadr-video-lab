# КАДР 3.3 — тестовый стенд E1/E2

Отдельный статический эксперимент для проверки источников, рекламы и управления видео. Это не разработка всего КАДРа и не подтверждение пригодности поставщиков.

**Публикация: NOT_RUN.** GitHub Pages при начале работы не был настроен (`has_pages=false`, Pages API — 404). Этот PR готовит публикацию **после независимого аудита и одобрения владельцем**. До проверки успешного deployment и его HTTPS-адреса сайт не считается опубликованным. Изменения не сливаются с `main` исполнителем.

Изменения отправлены в отдельную ветку `experiment/kadr-3-3`. Право записи проверено реальной отправкой в GitHub. Проверки PR и публикация из одобренного main — отдельные workflows.

## Что подтвердилось

| Кандидат | Gate | Что доступно |
| --- | --- | --- |
| AniLiberty v1 | VERIFIED_DOCUMENTATION | Без входа получены JSON релиза, HLS и 1024 байта сегмента. В URL оба рекламных флага = 1. |
| YapGrid | VERIFIED_DOCUMENTATION | Автор документирует публичный iframe по TMDB без ключа. Live embed в облаке дал 403: воспроизведение INCONCLUSIVE. |
| Stellar / Mapple / ezvidapi | INCONCLUSIVE | Первичные live-страницы дали 403. Их интеграции заблокированы; адреса не выдумываются. |

Проверки относятся к облачной среде, **не к сети РФ и не к физическому iPhone**. Бесплатность/ad-free — только заявления авторов там, где они прочитаны. Ни один поставщик не прошёл E1/E2 фактического просмотра. Подробнее: [матрица и условия](docs/providers.md), [сетевые свидетельства](evidence/probes.json).

## Как запустить с iPhone, без компьютера

1. Откройте Pull Request в Safari. Прочитайте изменения и результаты `Verify`. Проведите независимый аудит по [чек-листу](docs/review.md). Автотесты не заменяют его.
2. Если результат одобрен, самостоятельно объедините PR с `main` через **Merge pull request**. Это разрешает подготовленному workflow публикацию; до вашего одобрения исполнитель этого не делает.
3. В репозитории откройте **Settings → Pages**. В **Build and deployment → Source** выберите **GitHub Actions**. Если пункты скрыты, в меню Safari `aA` / меню страницы выберите «Запросить настольный веб-сайт». Терминал не нужен.
4. Откройте **Actions → Publish GitHub Pages**. Если предыдущий запуск после merge остановился из-за невключённого Pages, нажмите **Run workflow**, ветка **main**. Другие ветки этот workflow не публикует. В первый раз GitHub может запросить разрешение Actions или подтверждение среды `github-pages`.
5. Дождитесь зелёного задания **deploy**. Откройте **фактический адрес из результата deployment или Settings → Pages**. Здесь намеренно нет предполагаемой ссылки на неопубликованный сайт.
6. Проверьте, что открылась именно лаборатория 3.3, работают выбор источника и экспорт JSON, а `manifest.webmanifest` и `sw.js` по относительным адресам не дают 404. Сохраните ссылку на Actions, commit SHA, адрес и время проверки. Только после этого публикацию можно считать проверенной.
7. В Safari нажмите **Поделиться → На экран «Домой» → Добавить**. Откройте значок. Это тестовый PWA; установка и реальный просмотр на вашем iPhone ещё требуют проверки.

Если Pages или Actions недоступны по правам аккаунта, статус остаётся INCONCLUSIVE / NOT_RUN. Не вводите API-ключи и не включайте серверный прокси ради публикации. Сборка также подходит для другого бесплатного статического HTTPS-хостинга после отдельного решения владельца.

## Как провести испытание

1. Выберите поставщика и объект из выборки либо введите документированный ID. Для YapGrid нужен **TMDB**, для AniLiberty — **ID / alias релиза** и ordinal эпизода. IMDb не подставляется вместо TMDB; проверенного бесключевого конвертера нет.
2. Укажите реальный браузер, страну и тип сети, блокировщик и этап. Весь контент тестируется только в рамках вашего права доступа.
3. Нажмите **Открыть источник вручную**, затем Play в плеере. Отмечайте отдельно страницу, точное полное произведение, старт, 5 минут, seek, паузу, конец, рекламу и события.
4. Перед изменением условий нажмите **Новый сеанс**. Для повторной независимой сессии E2 полностью закройте вкладку / PWA и откройте снова. Результаты не сбрасываются.
5. Нажмите **Скачать JSON** или **Поделиться JSON**, сохраните в «Файлы». CSV доступен для таблиц. Не отправляйте файлы с персональными примечаниями в публичный PR.

Подробный [протокол E1/E2](docs/e1-e2.md) и [пустая матрица NOT_RUN](protocol/blank-results.json). Тест ПК остаётся NOT_RUN, пока нет возможности привлечь отдельного проверяющего с ПК; владельцу компьютер не требуется.

## Ограничения стенда

- Нет бэкенда, медиапрокси, собственной видеотеки, аналитики или полей секретных ключей. Байты видео идут напрямую поставщику. Внешний iframe может вести собственный трекинг.
- YapGrid не публикует проверенный контракт postMessage: сообщения отклоняются. Лог `iframe-load` не считается успешным просмотром. Нет доступа к DOM, запросам и дорожкам чужого iframe.
- По умолчанию iframe имеет `sandbox="allow-scripts allow-same-origin"`: окна и верхняя навигация запрещены. Сравнение с окнами / без sandbox — отдельные сеансы с предупреждением. Это не блокировка видеорекламы и не гарантия совместимости.
- HLS берётся только из поля официального API. Рекламные флаги и URL не меняются. Safari использует нативный HLS, совместимый десктоп — локально поставляемый hls.js 1.7.3. Новый медиадомен требует повторной проверки allowlist и CSP.
- Ручные результаты не повышаются до PASS по событиям. Журнал хранится в `localStorage` этого origin; Safari и PWA могут иметь разные данные. Приватный режим, очистка Safari, удаление PWA и квота могут удалить/ограничить хранение. Ошибка сохранения показана, экспорт из памяти остаётся доступен.
- До 240 записей, до 400 событий на запись; `timeupdate` не чаще раза в 30 секунд. Пропущенные по лимиту события считаются отдельно. Подробный сетевой трейс стенд не снимает. Неизвестный трекинг отмечайте INCONCLUSIVE, а не «не наблюдалось».
- Service Worker кеширует только конечный список собственных файлов интерфейса. API, сторонний iframe, манифесты видео, сегменты и журнал в кеш SW не попадают. В экспорте нет исходных HLS URL; только наблюдаемые origin.

## Файлы и проверки

- `web/` — исходники; `dist/` — сборка, создаётся Actions и не коммитится.
- `evidence/` — реальные сетевые пробы и контрактные выдержки; `protocol/` — физические тесты NOT_RUN.
- `tests/` — автоматические проверки обработчика событий, экспорта, хранения, изоляции и пользовательского пути. Их синтетические ответы не являются свидетельством доступности видео.
- `docs/verification.md` — реально выполненные проверки и пределы; `docs/review.md` — проверка безопасности и независимый аудит.
- Workflow `Verify` проверяет PR и создаёт резервный ZIP с исходниками и сборкой. ZIP доступен в **Actions → Verify → запуск → Artifacts → kadr-video-lab-3.3**. Это запасной артефакт, не замена Pages.

Для разработчика в облачной среде (владельцу выполнять команды не нужно):

```sh
npm ci
npm test
npm run build
npx playwright install --with-deps chromium
npm run test:browser
npm run package
```

Инструкции основаны на [официальной документации GitHub Pages с Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
