## Исправления по акту

| Замечание | Исправление и регрессия |
| --- | --- |
| №1: ложный E2 PASS | Разделены probeStatus и adFreeSessionStatus, смысл общего E2 PASS явно ограничен полным закрытым сеансом без рекламы и базовым контролем. Проверяются все пять рекламных категорий, конец и отдельная ручная отметка. Smoke не даёт итоговый PASS. Unit + browser проверяют исходный дефект, положительный полный сеанс и последующее изменение рекламы. |
| №2: нет основания E1 | Выбор ID предыдущего завершённого валидного E1 PASS того же источника и объекта / эпизода. Без него E2 только предварительный; причины есть в журнале и JSON/CSV. Смена сети не требует нового E1. Unit + browser покрывают отсутствие, неверный объект, незавершённый / неуспешный E1 и повтор на другой сети. |
| №3: режим без sandbox | Сильное предупреждение до запуска, отдельное подтверждение чистой тестовой сессии после strict-пробы; не первый тест на личном iPhone. Новый сеанс возвращает strict. Provider + browser тесты проверяют оба подтверждения и сброс. |

Старые E2 PASS без основания и достаточных наблюдений понижаются до INCONCLUSIVE при загрузке / сохранении / экспорте. Заметки сохраняются, условия не достраиваются как будто измеренные. Это отдельно проверяется unit и browser регрессиями.

## Что проверять в PR

- `providers.js`: исполняемые endpoints только из проверенных контрактов; три неподтверждённых кандидата заблокированы. AniLiberty HLS используется как получен, рекламные флаги не меняются. Защита схемы / домена не превращается в произвольный URL-resolver.
- `app.js`: iframe создаётся только после ручного действия; origin фиксирован, `sandbox` по умолчанию без окон/навигации. Снятие sandbox — явный отдельный режим с предупреждением. Cross-origin DOM не читается. Нет внешних пользовательских скриптов, SDK рекламы и аналитики.
- `core.js`: postMessage проверяет точные origin и source, размер/структуру и числовые поля; без документированного parser отклоняет всё. Тестовый parser из unit-теста не подключён к поставщикам. Raw payload не сохраняется и не выводится как HTML.
- Журнал различает NOT_RUN / PASS / FAIL / INCONCLUSIVE, загрузку iframe и старт видео, трекинг и рекламу. События не повышают ручные результаты до PASS. Противоречивое PASS понижено до INCONCLUSIVE.
- Ручные изменения сохраняются сразу; ошибки квоты / недоступного хранилища видны; повреждённые исходные данные не перезаписываются, возможна восстановительная копия. После reload источник не запускается автоматически. Старый запрос не должен менять новый сеанс.
- JSON экспортирует полную запись; CSV сохраняет Unicode, кавычки, переносы строк и нейтрализует формулы. Журнал не содержит исходных медиассылок, credentials или payload. Примечания владельца требуют ручной проверки перед передачей.
- SW кеширует только собственный интерфейс, не медиатрафик. CSP ограничивает iframe / API / медиа и локальные scripts. hls.js закреплён в lockfile и поставляется локально с лицензией.
- Workflows: PR только проверяется; Pages — только `main` после merge / ручного запуска с main. Нет `pull_request_target`, публикации из PR, пользовательских секретов или автоматического merge. Права публикации даны только deploy-job.
