# search-2: metadata, контролируемый A и закрытые результаты

База — e719d3e738fc02f7717bf5e905fa2da6b5c78b2d, актуальный main на начало 2026-10-24. Архив `archive/pre-metadata-control-e719d3e`. Старые history/docs/evidence/protocol/fixtures и Lift-журналы сохраняются. Основной КАДР не изменяется.

## Metadata

Порядок: один native HTTPS `.torrent`/xs/as от источника; совпадающий hash снимок metadata; BEP9 через WebRTC. Без родного URL/снимка не тратим время на заведомо недоступный itorrents.org. Ошибки не превращаются в утверждение об отсутствии webseed. Для BEP9 перечисление файлов и SHA-1 проверяются до выбора piece. В A HTTP-медиа выключены.

Дополнительный manifest `web/search-fixtures/metadata-sources.json` сохраняет дату и происхождение новых снимков отдельно от прежних девяти пакетов. Для f288db0e01560e7989b105a494a1d8e3674faaa8 metadata получены по `https://nyaa.si/download/1955560.torrent` (нативный поиск по infohash привёл к странице этого пакета), HTTP200, 69572 Б. SHA-1 исходного info dictionary совпал. Полный список: 12 видео, fileIdx1 — S01E02, 1682464444 Б. В исходном torrent отсутствуют url-list/httpseeds. Публикуется info dictionary, ненужные announce/comment поля удалены; это не меняет infohash. Снимок не объявляется live-ответом Nyaa; сам Nyaa не предоставляет CORS для этого GET.

Локальный импорт .torrent доступен в выбранной карточке: до 1 МиБ, общая квота metadata 4 МиБ на поиск, exact SHA-1 info dictionary, полный исходный fileIdx включая не-видео. Файл другого magnet отвергается до установки metadata. Импорт не скачивает видео; ручная повторная проба отдельно ограничена 20 с и оставшимся общим payload-бюджетом 16 МиБ. Неоднозначная серия требует явного выбора; соседний/крупнейший файл автоматически не подставляется.

В памяти metadata переиспользуются вместе с provenance. В экспорт не попадают сырые metadata, native URLs с параметрами, имя импортированного файла, SDP/IP или токены. В журнале остаются hash, источник, время, размер, fileIdx/path/length выбранного файла и раздельные счётчики.

## Сессии

Карточка замыкает свою SearchSession; каждый action проверяет текущего владельца, `cancelled` и принадлежность кандидата. После await проверки повторяются. При смене нижнего подключения или материала session инвалидируется до асинхронного teardown. Старые карточки и журнал читаются, кнопки запуска/выбора/пробы выключены. Захваченный до закрытия callback также не запускает старую или новую сессию. Новый поиск создаёт новый ID; история не очищается.

## Контроль разработчика

`.github/workflows/a-control.yml` использует существующий публичный GitHub Actions runner, временный браузерный сидер собственного `kadr-control-60s.mp4`, два свежих клиента и реальные публичные WSS-трекеры. Никаких ручных signaling shortcuts, HTTP-медиарезерва, изменения WebRTC policy или постоянного сервера. Seeder ready сам по себе не считается успехом: нужны hash, wire, отправленные/полученные видеобайты, проверенный piece и native playing с продвижением currentTime до полной загрузки.

Первый контроль: https://github.com/MawrikBorug/kadr-video-lab/actions/runs/40043418280 — PASS. BEP9: 484 Б сетевых metadata-сообщений, сериализованный torrent 594 Б, 1 wire, 32768 Б SHA-1-проверенного piece. Player A: 113967 Б WebRTC, 0 HTTP-медиа, preexistingBytesAtReady0, первый настоящий playing ~7.3 с, 640×360, запуск до полной загрузки. Это собственный контроль, не найденный коммерческий тайтл.

Разработческий запуск после публикации: `gh workflow run a-control.yml -f published=true -f metadata=true`. Сначала доказывается сидер, затем он остаётся доступным до 180 с для внешнего клиента. `SEEDER_RUN_ID=... node scripts/check-a-external-viewer.mjs` записывает пробу системного управляемого Chromium с опубликованного origin; временные отметки сопоставляются с externalWindow контрольного артефакта. Сетевые политики среды не изменяются. `check-followup-live.mjs` повторяет фактический поиск и три ограниченные пробы с published UI, сохраняет полный file list нового snapshot и проверяет старые callbacks после смены источника. Физический iPhone не выводится из этих тестов.

`resolve-control-metadata.py` — отдельная разовая разработческая диагностика native HTTPS/BEP9, не приложение и не сервер. Libtorrent работает в upload_mode + default_dont_download; видеопieces не запрашиваются, payload должен быть 0. При недоступном источнике сохраняется timeout, не поддельный file list. Такой native контроль не считается браузерным WebRTC.

## Короткая проверка iPhone

1. Открыть прежний URL в Safari, проверить сборку search-2, выбрать Дандадан S1E2 → «Найти и проверить». Дождаться ограниченной очереди.
2. У f288db… выбрать источник: metadata SHA-1, 12 файлов, выбран fileIdx1/S01E02/1682464444 Б. Найденный magnet, metadata, пир и видеобайты читать отдельно. Для другого .torrent: открыть сохранённый файл в «Файлах», сверить принятие/отказ SHA-1; затем выбрать точный путь.
3. «Проверить доставку выбранного источника» — до 20 с; при байтах запуск A, либо доступный B. Ноль байтов не считать воспроизведением. Контрольный сидер при необходимости запускает разработчик.
4. Сменить нижнее подключение или материал: старые карточки должны стать неактивными, панель запуска скрыться. Новый поиск снова даёт активные результаты; прошлый JSON остаётся в истории.
5. Экспортировать поиск JSON. Повторить после добавления на экран «Домой» как отдельный прогон; Safari/PWA и звук/декодирование подтвердить на устройстве.
