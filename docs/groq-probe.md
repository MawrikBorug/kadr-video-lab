# Groq: один ручной тест доступа

Это диагностический тест собственного доступа к `openai/gpt-oss-120b`, а не приёмка поиска, рекомендаций или разборов. Он отправляет один короткий синтетический текст, без кадров и пользовательских данных. Ответ модели не выводится. Нужен существующий **Free** Groq key; workflow не создаёт аккаунт, не включает billing и не проверяет тариф. Не использовать ключ платного проекта.

## Запуск после проверенного merge в main

Обычная кнопка `workflow_dispatch` появляется, когда workflow есть в default branch. До merge этот тест не запускать.

1. В [repository Actions secrets](https://github.com/MawrikBorug/kadr-video-lab/settings/secrets/actions) добавить существующий ключ с именем **GROQ_API_KEY**. Значение вводится только в GitHub Secret; не в чат, issue, исходники, Drive или форму приложения. Если секрет уже правильно настроен, этот шаг пропускается.
2. В [GitHub Actions](https://github.com/MawrikBorug/kadr-video-lab/actions) выбрать **Groq access probe (manual)** → **Run workflow**, оставить **main**, включить `confirm_one_request` и запустить один раз под владельцем **MawrikBorug**. Перед запуском открыть **Groq Console → Limits** и **Settings → Data Controls**, проверить собственную Free-квоту и Zero Data Retention. Если этого нельзя подтвердить, не передавать пользовательские данные; сам тест содержит только синтетическую строку.

Этот API-тест не может подтвердить настройки ZDR, региональную допустимость или все квоты аккаунта. Заголовки ответа — ограниченное наблюдение текущих лимитов, не гарантия будущей ёмкости. Не присылать скриншоты со значением ключа. Сохранить только значения Limits/состояние ZDR без секрета и идентификаторов аккаунта, если они нужны для следующей приёмки.

## Результат

В журнале и artifact `groq-access-probe-<run_id>/report.json` есть только HTTP status, фиксированный model ID, latency, проверенные числовые usage и allowlist квот. Артефакт хранится 7 дней. В public-репозитории логи/артефакт могут быть доступны другим: там нет тела запроса/ответа, но лимиты организации видны.

`ACCESS_CONFIRMED` подтверждает один авторизованный синтетический ответ с корректной формой. Его текст и качество не оценены. `ACCESS_CONFIRMED_INCOMPLETE` означает, что endpoint ответил, но генерация не завершилась обычным stop; это не PASS качества. `NOT_RUN_MISSING_SECRET` означает 0 попыток. 401/403/429 и другие HTTP-коды имеют отдельные статусы; ошибка не выводит provider body. Timeout/transport error может означать уже расходованную квоту: исход неизвестен, автоматического повтора нет.

Не использовать **Re-run jobs**: повторные attempts блокируются. Новый ручной workflow — новая потенциальная API-попытка; не запускать для устранения ошибки вслепую. Другой branch, fork, actor, отсутствие подтверждения и повторный attempt пропускают job; skipped job не является проверкой доступа.

## Изоляция и проверки

Workflow имеет только `contents: read`, не имеет schedule/push/PR trigger, работает только из main владельца. Секрет доступен только одному шагу probe. Checkout и upload-artifact закреплены SHA, credentials не сохраняются. Python stdlib использует фиксированный HTTPS host/path с проверкой сертификата, не следует redirect и не использует proxy env. Никаких сторонних SDK, произвольных URL/prompt/model inputs или retries.

`python3 -m unittest discover -s tests -p groq_probe_test.py` проверяет негативные пути на fake transport без сети. Тот же suite подключён к существующему `npm test` маленьким Node wrapper, поэтому Verify PR проверит его без секретов.

В Pages добавлены точные `paths-ignore` для шести файлов этого probe, включая `pages.yml`. Поэтому probe-only merge не публикует сайт. Любой push, затрагивающий иные пути, сохраняет прежний запуск Pages. Изменение только `pages.yml` само по себе теперь также не деплоит: при необходимости публикации после такого изменения используется существующий ручной Pages workflow. Verify сохраняется без изменений; исторический Controlled WebRTC A не запускается этой веткой.

Официальные основания model ID и заголовков: https://console.groq.com/docs/model/openai/gpt-oss-120b , https://console.groq.com/docs/rate-limits . Собственные Limits/ZDR и живой inference этим PR ещё не проверены.
